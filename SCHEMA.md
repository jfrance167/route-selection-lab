# Frozen version 1 contract

Coordinator 01:41 approval/addendum incorporated before code. This describes an original restricted installed-route teaching model, not router compliance or live route installation.

Envelope keys exactly version (integer 1), context, routes, destinations. Recognized context enum: destination_only, source_policy, tos_policy, vendor_route_installation, recursive_next_hop, flow_hash. Only destination_only is supported. Every context validates the entire common payload, including groups, before producing a result. Recognized unsupported contexts return status unsupported_policy, results [], and reason; never selected ids. Empty table is valid (queries produce no_model_route); empty destinations is valid (supported results [], exit 0; unsupported still exit 3).

Route keys: id, prefix, action; forward requires next_hop and egress and optionally ecmp_group. Discard forbids those forward fields. IDs, opaque fictional egress labels and groups are case-sensitive ASCII LDH tokens, 1..32, no leading/trailing hyphen. Unique route IDs. Prefix: exactly one slash, decimal prefix-length with no leading zeros, no netmask/zone/mapped-IPv6 syntax; strict host-bit rejection. Addresses only documentation blocks (192.0.2/24, 198.51.100/24, 203.0.113/24, 2001:db8::/32). Nondefault routes must lie wholly within one block; only mathematical defaults 0.0.0.0/0 and ::/0 are exempt. Queries/next_hops always documentation addresses of the appropriate family. IPv6 case/compression normalizes; original strings are preserved as escaped provenance. No special-address scope classifier, next-hop resolution or interface proof.

Canonical path identity: family + canonical prefix + action + canonical next_hop + exact egress label (latter two absent for discard). IDs and ECMP labels are never part of this identity. Duplicate identity is invalid, including aliases of IPv6 spelling, same default and same discard route. Canonically duplicate destination values invalid.

Each ecmp_group must contain >=2 distinct forward paths at one canonical prefix/family. At that prefix every route must be forward and declare that same group; no mixed group/ungrouped/discard or differently named groups. Group names cannot span prefixes. A group declaration records only fixture intent, not verified metrics or hardware ECMP. Same-prefix forward/discard without a group is valid and ambiguous; no discard priority fabricated.

Lookup uses same-family containment and maximum prefix length. One survivor → selected_forward/selected_discard. None → no_model_route. Several → ambiguous_equal_best unless they are exactly a valid declared group → declared_ecmp_candidates. Actual flow path is always unknown. A more-specific discard is selected without fallback. Equal survivors are reported sorted by ID, never resolved by sorting, metric or input order. Every input route has one trace reason: longest_match, shorter_match, different_family, does_not_contain. Prefix math doesn't treat IPv4 network/broadcast membership as reachable host permission.

Limits enforced by exact-bytes API and CLI: input 65536 bytes UTF-8, nesting 6, numeric tokens 10 chars, strings 128, routes 64, destinations 16, serialized output 262144 bytes. Reject duplicate/unknown keys, floats/constants, bool version, controls/DEL/surrogates/BOM, unsupported syntax and excessive collections. Public analyze(data) accepts type(data) is bytes, not subclasses/custom containers. Decode, common validation, analysis and output-budget validation finish before returning or CLI writing. No input-derived terminal errors. No address enumeration, sockets, subprocesses, OS routing APIs or actual devices in application.

Exits: 0 supported analysis (including ambiguity/discard/no_model_route/empty queries); 3 recognized unsupported context after valid common payload; 2 invalid input/argument/I/O or short write. stdout JSON only plus final LF; errors stderr. Semantic failures emit nothing. Physical writes are not transactional and short/failed delivery is honestly an error; shell redirection can itself truncate files.

## Independently fixed examples

Table r24=192.0.2.0/24, r25=192.0.2.0/25, rh=192.0.2.20/32 (distinct fictional forward paths): .20 → rh, .127 → r25, .128 → r24. A discard /25 over a forward /24 selects discard for .20. IPv4 default never matches 2001:db8::1; IPv6 default does. Host /128 beats /32 for its exact IPv6 destination. Two /24 paths with different next_hops and no group are ambiguous under any input permutation. Declaring group g on both yields declared_ecmp_candidates; no selected flow. Adding a discard at that grouped prefix is invalid. Changing only ID/group on a duplicate path remains invalid. source_policy with a valid table yields unsupported; same payload with host bits set is invalid first.

All fixture data is invented. Any wider route-installation/policy/scope/ECMP simulation needs a new reviewed contract.
